# 计费规则（PRICING）

> 本文档描述 relay-hub 的完整计费链路：下游收入（用户扣点）与上游成本（渠道支出），以及利润报表。

## 术语

| 术语 | 含义 | 配置位置 |
|------|------|---------|
| 标价 | 每千 tokens 的点数价：`price_in_per_1k` / `price_out_per_1k` | users.json 顶层（管理面「计费规则」） |
| 分组倍率 | 用户分组（vip 等）的折扣/上浮系数 | users.json `groups`（管理面「分组倍率」） |
| 分时倍率 | 峰时小时集合内标价 × `peak_multiplier`，谷时恒 1.0 | users.json `peak_hours` + `peak_multiplier` |
| 上游成本倍率 | 该渠道的货币成本系数（免费渠道填 0） | pool.json 每个渠道 `cost_multiplier` |
| 上游单价 | 该渠道的真实货币价（每 1k tokens），未配 = 成本未知 | pool.json `price_in_per_1k` / `price_out_per_1k` |

## 下游收入（用户扣点）

```
扣点 = ceil( (tokens_in/1000 × price_in + tokens_out/1000 × price_out)
             × 分组倍率 × 分时倍率 )
```

- 预扣（pre-consume）：按输入体量先冻结预估点数，完工后按实际用量多退少补——堵「发大 prompt 中途断开白嫖上游」的洞。
- 流中断：按预扣额结清（上游已消费整段输入）。
- 额度 -1 = 不限量，不参与计费；0 = 禁用。

### 分时计费

管理面「用户」→「计费规则」配置：

- **峰时小时**：逗号分隔的 0-23 小时，如 `9,10,11,14,15,16,17,18,19,20,21`；留空 = 不启用。
- **峰时倍率**：≥1.0；峰时（本机时区小时 ∈ 峰时集合）扣点 = 标价 × 倍率，谷时 = 标价。

请求记账按**请求开始时刻**取倍率，写入请求日志（可审计每笔的峰谷归属）。

## 上游成本（渠道支出）

```
上游成本 = ceil( (tokens_in/1000 × 渠道price_in + tokens_out/1000 × 渠道price_out)
                 × 渠道cost_multiplier )
```

- **免费渠道**：`cost_multiplier = 0` → 成本恒 0。
- **未配单价**（两个价都 0）：成本记 0，语义是「没配价算不出」——不要在报表里当成免费利润。
- 成本按实际服务的渠道计入请求日志 `upstream_cost` 字段。

## 利润报表

管理面「用量」页顶部卡片：**收入（点）/ 上游成本（点）/ 利润（点）**，支持按日 / 令牌 / 模型 / 渠道分桶（每桶均含 cost 与 upstream_cost 列）。

```
利润 = Σ(用户扣点) − Σ(上游成本)
```

## 渠道分组与路由

- 每个渠道一个**组**（`free` / `paid` / `stable` … 自定义），管理面「渠道」编辑。
- 同一模型出现在多个组时各组**独立调度**；**组内 failover，绝不跨组自动切换**——免费挂了自动切付费是事故不是容错。
- 下游令牌可绑定 `channel_group`：该令牌的请求只路由到该组；组外模型一律 404「不在列表」。绑定空 = 全部组。
- 用户面板「可用模型」即按名下启用令牌的组并集过滤后的列表。

## 兑换码

- 管理面「用户」→「兑换码」：`POST /api/codes` 批量生成（数量 × 每张点数），**明文只回显一次**。
- 用户在 `/panel` 输入 `rhx-…` 兑换，一次性核销，点数即时入账。
